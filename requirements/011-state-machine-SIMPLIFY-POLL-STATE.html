Partly superseded by 012-ADMIN-REVISIONS

This is the 011 state-machine reference and is accurate for 011. Four of its statements no longer hold after 012. Everything else still applies.

  1. EDITING is no longer always hidden. A poll being edited stays in the public listing if the public had already seen it (its pre-edit state was WAITING TO OPEN, OPEN or CLOSED), so its card can carry a “momentarily unavailable” message instead of vanishing mid-edit. A poll the public had never seen — INITIALIZED or REJECTED — is still withheld. 012 FR-046.
  2. Administrators can now drive OPEN, CLOSED and ARCHIVED directly from the poll list, in addition to the schedule sweep. OPEN is allowed from WAITING TO OPEN or CLOSED; CLOSED from WAITING TO OPEN or OPEN; ARCHIVED still only from CLOSED. 012 FR-024.
  3. Archiving no longer stamps endAt = now. It writes the state and nothing else, so a poll keeps the date it actually closed. The manual OPEN and CLOSED transitions write the schedule so the date sweep confirms them rather than reverting them — there is still no override flag. 012 FR-025–FR-028.
  4. A vote refused because the poll is being edited now returns a distinct message and the code POLL_EDITING, so the card can offer a retry rather than the closed-poll treatment. 012 FR-044.

Poll Lifecycle State Machine

Eight states, ten events, three named background sweeps. Every cell in the event grid is defined, every field's writers and clearers balance, and every path out of every state terminates. Nothing is left open.

Four structural facts fall out of the grid. ARCHIVED is terminal because nothing in its row moves it. The three sweeps act on disjoint sets of states, so they can never contend for the same poll. For the spec

Decisions worth recording

These are choices the document makes deliberately, each of which a reader might otherwise take for a mistake. They belong in the specification's Assumptions section rather than being rediscovered at implementation time.

Choices freeze at the first vote, not at publication
A WAITING TO OPEN, OPEN or CLOSED poll that nobody has voted in yet is fully editable, choice list included (lines 31–32, 48–51). EDITING hides the poll while it changes, so the public never watches a choice list mutate — but a poll can leave the grid and come back different.
The editing lock is not re-enterable by its holder
A refresh or a second tab generates a new GUID and is refused, costing the admin up to 40 seconds (lines 110–115). Accepted deliberately, with a stated user-facing message.
Publishing is asynchronous
saveAndPublishPoll returns immediately and the author lands back on adminPoll before the poll has been judged (lines 195–205). On the happy path the real outcome arrives within about 15 seconds.
A screening outage is bounded, then handed to a person
Ten counted attempts, then REJECTED with an explanatory reason and a re-attempt button on adminPoll (lines 295–307). Beyond that, line 312 says resolution requires a code or API change — the system does not keep trying forever.
One app instance is assumed
All three sweeps are plain timers; line 343 records that a future requirement moves them into a singleton serverless function. Until then, running two instances would double every sweep.
No migration
The poll and vote collections may be dropped and recreated (lines 373–378). The (removed) tombstone concept disappears from both choices and votes.
