# Implementation Plan: Site Favicon

**Branch**: `dev` (no dedicated branch) | **Date**: 2026-10-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/20261016-172002-FAVICON/spec.md`

## Summary

Add the site's favicon as two files in `src/public/`:
- `favicon.svg`: the two figures of the header's brand logo, without the speech bubble, on a transparent square (`viewBox="10 4.5 96 96"`), titled `CrowdPoll` (research R4).
- `favicon.ico`: 16, 32 and 48 px PNG images, made from the SVG by a new hand-run script, `devScripts/favicon-ico.ts`. The script renders the SVG with headless Microsoft Edge and writes the ICO container itself (R5).

All seven pages get two `<link rel="icon">` tags right after the viewport `<meta>` (R3). The existing asset pipeline fingerprints both files, rewrites the links to the immutable copies and publishes them to Spaces, with no change (R1). The existing `express.static(publicDir)` answers the browser's bare `/favicon.ico` (R2).

`tests/pages.test.ts` gains three checks: the links on every page, `GET /favicon.ico`, and the ICO's three sizes (R6).

No server, route, configuration, data or migration change. No new dependency; one `.gitignore` exception.

## Technical Context

**Language/Version**:
- static SVG and ICO in `src/public/`;
- HTML edits to the seven pages;
- one TypeScript dev script run with `tsx`;
- TypeScript tests;
- Node ≥ 22.

**Primary Dependencies**: None new. `devScripts/favicon-ico.ts` uses only `node:child_process`, `node:fs`, `node:os` and `node:path`, and drives an installed Chromium-based browser: `FAVICON_BROWSER`, defaulting to Microsoft Edge's install path.

**Storage**: N/A. Two committed binary/text assets; no stored data.

**Testing**: Vitest + supertest in `tests/pages.test.ts`, run on the existing embedded-PostgreSQL test context. The look is checked by eye in light and dark browser tab strips (quickstart).

**Target Platform**: Every browser the site supports. Browsers with SVG-icon support use `favicon.svg`; the rest use `favicon.ico`.

**Project Type**: Web application. Static pages are served by the existing Express server and fingerprinted by `devScripts/build-assets.ts`.

**Performance Goals**: Two small files on the existing one-year immutable asset path; one root `/favicon.ico` with `express.static`'s ETag caching.

**Constraints**:
- no build step, so `npm run build` is unchanged (FR-008);
- the header logo is unchanged (FR-009);
- no explanatory comments in the new files (Constitution VI);
- the ICO is regenerated only by the script.

**Scale/Scope**:
- 2 new assets (`favicon.svg`, about 20 lines; `favicon.ico`, about 2 KB);
- 1 new script (`devScripts/favicon-ico.ts`, about 60 lines);
- 2 new lines in each of the 7 pages;
- 1 `.gitignore` line;
- 1 edited test file;
- 2 documentation files updated (`README.md`, `ARCHITECTURE.md`, Phase 7).
